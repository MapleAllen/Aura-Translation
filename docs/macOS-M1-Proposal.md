## 1. 结论与定位

项目已经具备可继续迭代的桌面应用基础。首个新里程碑建议命名为 **M1：macOS 日常可用版**，重点从功能覆盖转向操作一致、安静常驻、首次使用简单和可测量的性能。保留 Tauri 2 + Rust + Svelte 5；没有证据表明此时重写 SwiftUI 能抵消迁移成本。

产品承诺：复制文字，按一次快捷键看到译文，按 Esc 收起，继续原来的工作；随时从菜单栏打开、暂停自动翻译或退出。

默认假设：先服务个人 macOS 日常使用，以当前 Apple Silicon Mac 为首个验收设备；中文界面，自动检测原文、默认译为中文，方向可改；用户自备翻译服务凭据或已有 Ollama。Intel 与最低 macOS 版本须在发布前明确并验证。普通用户无需自备 API key 的服务模式涉及独立的成本、账户与服务端设计，不应默认为本里程碑的一部分。

## 3. 优先解决的问题

### P0：开关和快捷键必须可预测

> 已实施。决策逻辑提取为 `src-tauri/src/interaction.rs::decide_hotkey`，两个模式共用同一路径；同文复用按完整请求身份（文本、语言方向、服务商、模型、地址、配置方案）判定；菜单栏左键改为展开含「打开翻译 / 自动翻译 / 设置 / 退出」的菜单；翻译窗新增 IME 安全的 Esc 收起。

- `lib.rs::handle_hotkey_pressed` 在自动模式启用时有显隐分支；手动模式直接 `trigger_translation`。README 所述“再次按快捷键召回或隐藏”并非两个模式统一成立。这会让用户误发请求，也难以形成操作习惯。
- 菜单栏目前只有配置方案、设置、退出；左键不弹菜单而走召回逻辑。暂停自动翻译必须进入设置，不符合“轻松关闭”。
- 设置窗有 Esc 处理，翻译窗未发现对应窗口级 Esc 处理。应统一关闭行为，且不能干扰输入法组合输入。
- 未发现 single-instance、macOS 激活策略或 reopen 事件的显式集成；重复启动、Finder 再打开、Dock/应用切换表现列为待真机验证，不据此断言运行故障。

建议统一规则：

| 动作/状态 | M1 目标行为 |
| --- | --- |
| 新复制非空文本后按快捷键 | 翻译新文本；取消旧请求，旧结果不能覆盖新结果 |
| 相同文本且窗口可见时按快捷键 | 收起窗口，不重复付费请求 |
| 相同文本且窗口隐藏时按快捷键 | 召回现有结果，不重发请求 |
| 剪贴板为空时按快捷键 | 打开可直接输入的空态，提供简短提示 |
| Esc / 关闭翻译窗 | 隐藏浮窗；固定状态也可明确关闭；关闭导致当前请求取消且不再弹完成通知 |
| 重新翻译按钮 | 明确允许同一文本发起新请求 |
| 点击菜单栏图标 | 展示可发现的操作菜单：打开翻译、自动翻译开关、设置、退出 |
| 暂停自动翻译 | 停止自动读取正文和自动请求；手动快捷键继续可用 |
| 退出 Aura | 结束进程、释放快捷键、停止监测和在途请求 |

相同请求判定应包括文本、语言方向、服务商、模型和配置身份；修改翻译设置后不得错误复用旧结果。另需约定失焦时继续后台翻译还是取消：建议失焦仅收起、请求继续但静默，主动关闭则取消。

### P0：首次设置负担过高

> 已实施。新增显式 `setup_completed` 字段（老配置缺失时按就绪状态或已存窗口位置推断，升级用户不会被重新引导），引导收敛为「选择服务 → 验证凭据 → 试译一条」三步，只有试译成功才写标志；设置导航由六项收敛为三项 + 高级组。

当前设置包含六个入口：概览、翻译默认值、模型与密钥、触发方式、配置方案、历史记录。虽然已经分区，用户仍需理解服务商、模型、语言、快捷键和配置方案才能完成首次使用。

建议首次引导只保留三步：选择服务 → 填凭据并验证 → 试译一条示例。服务默认地址和模型预填；自定义地址、模型列表、存储降级放入高级项。成功后直接展示实际快捷键和菜单栏入口。已有配置直接复用，不强制重新引导。

引导完成应有明确持久化字段，不能依赖“设置窗位置已保存”等间接状态。普通设置收敛为“通用、翻译服务、历史”；多配置方案保留到高级区。API key 获取本身仍有学习成本，文案必须说明需要已有服务账户。

### P0：轻量需要实测与真实停用

> 已实施。监测循环改为先读配置再决定是否触碰 `NSPasteboard`，关闭态不做任何剪贴板调用并在重新启用时重置基线；`Client::new()` 替换为显式 `connect_timeout`(10s) 与 `timeout`(45s)，并让传输错误携带原因链。CPU 门槛按第 6 节的说明替换为可观测的行为断言。

`spawn_clipboard_monitor` 在 macOS 每 275ms 唤醒并读取 changeCount，然后才检查 `aura_mode_enabled`。关闭时不读取剪贴板正文，但循环和变化计数查询仍继续。模块文档中“关闭即停止轮询”的描述不准确。

建议启停采用状态通知控制任务休眠；启用时重置变化基线，避免补翻译停用期间复制的旧内容。先保留启用状态下的轮询实现，测量后再决定是否改变频率；不假设 macOS 存在可直接替换的通用剪贴板监听 API。

共享 HTTP client 当前使用 `Client::new()`，未显式配置网络超时；前端的 20 秒超时仅覆盖 loading。应在后端定义连接、首包和流停滞超时及取消语义，防止 UI 已失败但请求仍悬挂。已有取消/重试能力可复用，无需重写翻译引擎。

### P1：让译文成为界面主体

> 已实施。译文与「复制译文」为主体，语言方向/服务商/模型/token 移入「详情」折叠区；系统字体优先、深浅色语义色、45 处硬编码白底全部替换、圆角 10px、支持减少动态效果；草稿输入不再依赖固定态；窗口手动缩放后不再被自动尺寸抢回。

- 当前浮窗显示状态、上下文、原文、固定和 token 用量，部分辅助文字仅 11px。默认只突出译文、复制、关闭；原文折叠，模型和 token 移到详情。
- 草稿输入目前与固定状态绑定，用户需理解“固定”才能方便地直接输入。空态提供输入入口；固定仅影响窗口是否因失焦关闭。
- `ui/app.css` 以微软雅黑为优先字体，色彩为浅色固定值，外壳圆角为 0。采用 macOS 系统字体优先，建立浅/深主题语义色，消除组件内硬编码白色背景，再调整细边框、圆角与阴影。
- 保留已有流式输出；限制自动调高频率和最大高度，长文内部滚动，用户手动缩放后不要持续抢回尺寸。
- 补充全键盘访问、清晰焦点、按钮可访问名称、减少动态效果偏好和 VoiceOver 检查。不能只依赖 hover 或颜色表达状态。
- 已有系统通知只在翻译窗口隐藏时发送；建议默认静默处理后台成功和重试，在窗口/菜单中呈现错误，通知作为显式选项，避免读文章时不断打断。

### P1：建立 macOS 验收与分发闭环

> 部分实施。已补充可在 Mac 执行的四个脚本（stub 服务请求计数、资源采样含剪贴板帧检查、启动分位数、交互验收），并更正了配置路径为 `~/Library/Application Support/aura-translation/`。签名、公证与安装包仍属发布阶段，未开始。

macOS 脚本尚缺对应的资源测量和安装验收；现有 release 脚本为 PowerShell。补充可在 Mac 执行的检查步骤、产物归档、版本信息和全新配置验收。

个人自用阶段可用 `.app`；若目标包含发给普通用户，签名、公证、安装包和另一台 Mac 的 Gatekeeper 验证应成为发布门禁。Tauri 官方提供对应[签名与公证流程](https://v2.tauri.app/distribute/sign/macos/)，Apple 也明确区分[公证与 App Review](https://developer.apple.com/documentation/Security/notarizing-macos-software-before-distribution)。此建议不意味着本次申请证书、上传或发布。

## 4. 首版范围

必须交付：手动翻译闭环、明确显隐/退出、菜单栏自动翻译开关、简单引导、可恢复错误、舒适阅读、低后台开销、安装后日常验收。自动翻译沿用默认关闭，开启前说明复制文本会发送至所选服务；Aura Guard 只是辅助筛查，不承诺识别全部敏感文本。

保留但降低显著性：历史记录、配置方案、模型高级项、token 用量、草稿重译。历史增加是否保存的明确设置，现有本地数据和 Keychain 迁移须可回归验证。

延期：OCR、划词取词、截图翻译、自动粘贴回源应用、账号同步、内置模型下载器、更多服务商、复杂工作流、周期健康探测。Windows 继续保持现有回归检查，但不与本次 macOS 功能扩展绑定。

## 5. 建议能力边界与推进顺序

以下是供评审的能力地图，沿用现有模块，不新增平行架构或逐模块实现规格。

| 模块 id | 责任 | 依赖 |
| --- | --- | --- |
| translation-runtime | 请求身份、超时、取消、结果状态 | 现有翻译/配置模块 |
| desktop-lifecycle | 快捷键、窗口显隐、菜单、监测启停、重复启动 | translation-runtime |
| first-run | 配置迁移、服务验证、首次成功试译 | translation-runtime、desktop-lifecycle |
| translation-experience | 输入、译文、复制、固定、主题与无障碍 | desktop-lifecycle |
| macos-acceptance | 构建产物、性能采样、安装和日常验收 | 上述模块 |

推进建议：

1. **恢复基线**：确认本次测试结果；处理依赖审计与 Node 版本约束；用干净配置建立性能及真机行为基线。交付可重复的验证记录。
2. **打通操作闭环**：先明确请求/关闭状态，再修改快捷键、Esc、菜单栏开关、监测休眠和网络超时。交付不重复请求、能随时收起退出的一条完整流程。
3. **降低学习成本**：简化引导与设置，空态可输入，隐藏高级信息，改善错误恢复。交付无需读 README 的首次翻译。
4. **打磨 macOS 体验**：主题、字体、窗口层级、焦点、全屏/多屏、减少动态效果和通知策略。交付持续使用体验。
5. **验收并封版**：性能采样、真实服务试译、旧配置迁移、安装和五天日常试用；若公开分发，再完成签名公证门禁。

避免先拆整个 `lib.rs` 或升级全部主版本。`lib.rs` 约 1862 行、`SettingsPanel.svelte` 约 1046 行，确有维护压力；只随相关功能提取窗口、菜单、监测等职责，使行为变化与重构保持可评审。

## 6. “流畅、优雅、轻量”的候选验收标准

以下数值是建议目标，尚非实测，也不是所有 Mac 的承诺。使用 release 构建、记录设备/系统/文本长度，网络耗时与本机耗时分开统计。

| 维度 | 候选门槛 | 测法 |
| --- | --- | --- |
| 首次使用 | 已有可用凭据时，3 分钟内完成配置和第一条翻译 | 全新配置；邀请 3 位未读说明的人走流程，记录卡点 |
| 开关 | Esc 一次收起；菜单直接暂停/退出；同文召回不发送新请求 | 用 mock 服务计数，覆盖显示、隐藏、固定、进行中、配置变化 |
| 本机响应 | 热唤起可见 p95 ≤ 200ms；关闭 p95 ≤ 100ms | 30 次测量，从快捷键事件到窗口可交互，不包含服务响应 |
| 冷启动 | 菜单栏可操作 ≤ 2s | 10 次无 dev server 的启动；记录冷/暖缓存 |
| 稳定性 | 连续 100 次唤起/收起无失焦卡死和明显单调内存增长 | 相同场景记录首末及中间样本；包括重启、睡眠恢复 |
| 后台资源 | 自动模式关闭时 CPU 均值 < 0.5%，无周期剪贴板查询、无闲置网络请求 | 空闲 10 分钟；记录主进程与关联 WebKit 进程，排除开发服务器 |
| 内存 | 暂以应用及可归属 WebKit 进程合计 ≤ 150MB 为预算 | 先测冷启动、翻译后、设置关闭后基线；本地 Ollama 模型单独报告 |
| 翻译恢复 | 断网、401、429、首包超时、流停滞均有可理解提示和明确重试入口 | mock 注入失败；真实服务只验证正常链路与凭据 |
| 桌面适配 | 全屏应用、双屏不同缩放、拔屏、深色模式下不丢窗、不越界 | 真机矩阵，记录系统版本和是否通过 |
| 日常可用 | 连续 5 个工作日不需要强制结束进程，不出现停用后自动发送 | 日常试用问题清单，P0 清零后封版 |

低学习成本的最终证据来自实际首次使用，而不是设置页面更漂亮。低资源占用要包含 WebKit 进程；不能仅凭 Tauri 架构宣称已经轻量。
