# Translation History Module Description

## Module Name

Translation History

## Purpose

Translation History gives users a persistent audit log of their recent translation requests. Every successful or failed translation is recorded automatically with its source text, translated output (or error message), language pair, provider, model, token usage, and timestamp. Users can review, copy, retry, and delete individual entries or clear all history from the Settings panel. The history is capped at 50 entries and is stored on disk so it survives app restarts.

## Current Implementation

`TranslationHistoryStore` is an in-memory ordered list of `TranslationHistoryEntry` records, backed by `{config_dir}/aura-translation/history.json`. At startup, `TranslationHistoryStore::load()` reads the file. If absent, an empty store is written and returned. Parse or read failures are logged with `eprintln!` and an empty store is used.

Every call to `record_success()` or `record_error()` creates a new `TranslationHistoryEntry` and calls `insert_entry()`, which prepends the entry to the front of the list (newest-first ordering) and immediately persists the updated list to disk. If the list exceeds 50 entries after insertion, it is truncated to `MAX_HISTORY_ENTRIES = 50`.

Entry IDs are generated by `next_history_id()`: a millisecond timestamp combined with a monotonic `AtomicU64` counter, formatted as `"history-{ms}-{sequence}"`.

`delete()` removes a single entry by ID and saves. `clear()` empties the entire list and saves. Both return the updated entry list so the frontend can refresh its view without a separate `list()` call.

Saves use the same atomic write-then-rename pattern as `config.json`: the list is serialised to `history.json.tmp` then renamed into `history.json`.

### Capabilities

**Recording**
- `record_success(source_text, translated_text, source_lang, target_lang, provider, model, usage)`: records a completed translation with optional `TranslationUsage` token counts
- `record_error(source_text, error_message, source_lang, target_lang, provider, model, usage)`: records a failed translation; `translated_text` is stored as an empty string
- Entries are inserted newest-first; the list is pruned to 50 entries after every insert

**Retrieval and management**
- `list()`: returns all entries in newest-first order
- `find(entry_id)`: looks up a single entry by ID (used for retry flows)
- `delete(entry_id)`: removes an entry and returns the updated list
- `clear()`: empties all history and returns an empty list

**Token usage visibility**
- `TranslationUsage` struct: `prompt_tokens`, `completion_tokens`, `total_tokens` (all `u64`)
- Usage is optional (`Option<TranslationUsage>`) and is populated only when the active provider streams usage metadata
- The `usage` field defaults to `null` when deserialised from older history entries that predate usage tracking

**Frontend display**
- `HistoryList.svelte` renders the entry list in newest-first order
- Each row shows: status badge (success/error), language pair, provider and model, timestamp, and total token count (when available)
- Expanding a row reveals the full source text, translated text or error message, and per-segment token counts
- Copy, Retry, and Delete actions are available per entry
- Clear All shows a 5-second confirmation guard before committing

## Architecture

Service-layer pattern. The Rust `history.rs` module owns the `TranslationHistoryStore`, all persistence, and the entry data model. The `HistoryState` managed state in `lib.rs` wraps the store in a `Mutex<TranslationHistoryStore>`. Tauri commands bridge CRUD operations to the frontend. The TypeScript side holds mirrored type definitions and helper formatting functions.

### Rust Backend (`src-tauri/src/`)

- `history.rs`
  - `MAX_HISTORY_ENTRIES`: `50` — hard cap on stored entries
  - `TranslationUsage`: `{ prompt_tokens: u64, completion_tokens: u64, total_tokens: u64 }`
  - `TranslationHistoryStatus`: `Success | Error` (serialised as `"success" | "error"`)
  - `TranslationHistoryEntry`: full entry record
    - `id`: `"history-{ms}-{counter}"`
    - `source_text`, `translated_text`, `error_message: Option<String>`
    - `source_lang`, `target_lang`: language codes (e.g. `"auto"`, `"Chinese"`)
    - `provider: Provider`, `model: String`
    - `usage: Option<TranslationUsage>` — `#[serde(default)]` so older entries deserialise cleanly
    - `status: TranslationHistoryStatus`, `created_at_ms: u64`
  - `TranslationHistoryStore`: `{ entries: Vec<TranslationHistoryEntry> }` (private field, public methods only)
    - `load()`: reads `history.json` or returns empty default
    - `list()`: clones and returns all entries
    - `find(entry_id)`: linear scan by ID
    - `record_success(...)`: builds and inserts a Success entry
    - `record_error(...)`: builds and inserts an Error entry with empty `translated_text`
    - `delete(entry_id)`: removes by ID, saves, returns updated list
    - `clear()`: empties list, saves, returns empty vec
    - `insert_entry(entry)` (private): prepends, truncates to 50, saves
    - `save()` (private): serialises `entries` to pretty JSON, writes atomically via `.json.tmp` rename
  - `history_path()`: `{config_dir}/aura-translation/history.json`
  - `next_history_id()`: `"history-{current_timestamp_ms()}-{COUNTER.fetch_add(1)}"` using `AtomicU64`
  - `current_timestamp_ms()`: milliseconds since Unix epoch via `SystemTime::now()`

### Frontend (`ui/lib/`)

- `translationHistory.ts`
  - `TranslationUsage`: `{ prompt_tokens, completion_tokens, total_tokens: number }`
  - `TranslationHistoryStatus`: `'success' | 'error'`
  - `TranslationHistoryEntry`: TypeScript mirror with all fields from the Rust struct
  - `formatHistoryTimestamp(timestampMs)`: formats a Unix-ms timestamp using `Date.toLocaleString()`
  - `formatTokenCount(tokenCount)`: formats a number using `toLocaleString()` for locale-aware digit grouping

- `HistoryList.svelte`
  - Props: `entries: TranslationHistoryEntry[]`, callbacks `oncopy`, `onretry`, `ondelete`, `onclear`
  - `expandedEntryId: string | null` — controls the single-entry expand/collapse toggle
  - `confirmingClear: boolean` — 5-second auto-expiring confirmation guard for Clear All
  - `clearConfirmTimer` — `setTimeout` handle; cleaned up via `$effect` on component destroy
  - Shows an empty-state placeholder when `entries.length === 0`
  - Retry button always visible; Copy button visible only when `entry.translated_text` is non-empty

### Integration Points

- `src-tauri/src/lib.rs`
  - `HistoryState` (`Mutex<TranslationHistoryStore>`): managed Tauri state
  - `get_translation_history()`: returns `store.list()`
  - `delete_translation_history_entry(entry_id)`: calls `store.delete(entry_id)`
  - `clear_translation_history()`: calls `store.clear()`
  - Translation completion in `translate.rs` (via `lib.rs` callback) calls `store.record_success()` or `store.record_error()` and emits a `translation-history-updated` event to the frontend

- `src-tauri/src/translate.rs`
  - After streaming completes or errors, the translation result (or error message) is passed back to `lib.rs` which calls the `HistoryState` mutation

- `ui/lib/SettingsPanel.svelte`
  - Invokes `get_translation_history` on mount
  - Listens for `translation-history-updated` event and refreshes the list
  - Passes `entries` to `HistoryList` and handles `oncopy`, `onretry`, `ondelete`, `onclear` callbacks
  - Retry action: looks up the entry by ID and re-invokes translation with the stored source text

## Current Limitations

- **`eprintln!` on parse failure**: history file parse errors are not routed through `daemon-error`.
- **In-memory only during session**: history entries recorded during a session are only visible to the frontend after a `translation-history-updated` event; there is no live reactive store that updates automatically.
- **Retry re-uses stored provider and model, not the current profile**: when the user retries from history, the retry uses the stored `source_text` but the current active provider/model, not the provider/model recorded in the entry.
- **No search or filter**: the history list has no text search, language filter, or status filter.
- **50-entry hard cap**: entries beyond 50 are permanently discarded; there is no configurable limit.
- **No export**: history cannot be exported to a file.

## Future Directions

- Emit history parse failures through `daemon-error` for consistent error surfacing.
- Add text search and status/language filter controls to `HistoryList.svelte`.
- Make the history cap configurable in `AppConfig` (with a reasonable default of 50).
- Add a history export action that writes the entry list to a user-chosen JSON or CSV file.
- Show history entries in the translation bubble itself (a "Recent" tab or expandable section) for quick access without opening Settings.
- Support retry-with-original-provider by storing the provider/model snapshot and using it when the user explicitly requests it.
